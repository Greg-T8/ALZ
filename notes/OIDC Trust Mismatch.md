## Cause

This is an OIDC trust mismatch, not a Terraform, storage firewall, or Azure RBAC failure.

Terraform uses the plan managed identity (`ARM_CLIENT_ID aff7…`) to access the remote state. Microsoft Entra rejects GitHub’s token before Azure Storage is contacted:

`AADSTS700213: No matching federated identity record found`

The mismatch is:

| | OIDC subject |
|---|---|
| Generated by ALZ bootstrap v7.2.1 | `repo:T8Nation/alz-mgmt:environment:alz-mgmt-plan:...` |
| Sent by GitHub | `repo:T8Nation@306490163/alz-mgmt@1306510190:environment:alz-mgmt-plan:...` |

You can see the incoming subject in the [failure log](<C:/Users/gregt/LocalCode/Lab/ALZ/github_actions_logs/16_Post Checkout Code.txt:179>). The bootstrap constructs the older name-only subject in [locals.tf](C:/Users/gregt/LocalCode/Lab/ALZ/output/bootstrap/v7.2.1/modules/github/locals.tf:28).

GitHub changed repositories created after July 15, 2026 to use immutable OIDC subjects containing owner and repository IDs. Your repositories are using that new format. Microsoft Entra requires issuer, audience, and subject to match exactly. [GitHub OIDC reference](https://docs.github.com/en/actions/reference/security/oidc), [Microsoft workload identity federation](https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation).

The current ALZ bootstrap release is v7.2.1 from April 29, before GitHub’s rollout. [Bootstrap v7.2.1 release](https://github.com/Azure/accelerator-bootstrap-modules/releases/tag/v7.2.1).

## Recommended immediate repair

Keep GitHub’s more secure immutable subjects and add parallel federated credentials to the existing managed identities. Adding new credentials avoids Terraform immediately reverting a manually edited credential.

After signing back into Azure, run:

```powershell
az login --tenant "547b168b-bd3f-4cfc-ae2b-665f52672fae"
az account set --subscription "e091f6e7-031a-4924-97bb-8c983ca5d21a"

$rg       = "rg-alz-mgmt-identity-southcentralus-001"
$issuer   = "https://token.actions.githubusercontent.com"
$audience = "api://AzureADTokenExchange"

$repo = "repo:T8Nation@306490163/alz-mgmt@1306510190"
$cd   = "T8Nation/alz-mgmt-templates/.github/workflows/cd-template.yaml@refs/heads/main"
$ci   = "T8Nation/alz-mgmt-templates/.github/workflows/ci-template.yaml@refs/heads/main"

# Continuous Delivery: plan
az identity federated-credential create `
  --resource-group $rg `
  --identity-name "id-alz-mgmt-southcentralus-plan-001" `
  --name "alz-mgmt-southcentralus-001-cd-plan-immutable" `
  --issuer $issuer `
  --audiences $audience `
  --subject "${repo}:environment:alz-mgmt-plan:job_workflow_ref:$cd"

# Continuous Delivery: apply
az identity federated-credential create `
  --resource-group $rg `
  --identity-name "id-alz-mgmt-southcentralus-apply-001" `
  --name "alz-mgmt-southcentralus-001-cd-apply-immutable" `
  --issuer $issuer `
  --audiences $audience `
  --subject "${repo}:environment:alz-mgmt-apply:job_workflow_ref:$cd"

# Continuous Integration: plan
az identity federated-credential create `
  --resource-group $rg `
  --identity-name "id-alz-mgmt-southcentralus-plan-001" `
  --name "alz-mgmt-southcentralus-001-ci-plan-immutable" `
  --issuer $issuer `
  --audiences $audience `
  --subject "${repo}:environment:alz-mgmt-plan:job_workflow_ref:$ci"
```

These names follow the defaults in your generated bootstrap configuration. You can confirm them first:

```powershell
az identity federated-credential list `
  --resource-group $rg `
  --identity-name "id-alz-mgmt-southcentralus-plan-001" `
  --query "[].{Name:name,Subject:subject}" -o table

az identity federated-credential list `
  --resource-group $rg `
  --identity-name "id-alz-mgmt-southcentralus-apply-001" `
  --query "[].{Name:name,Subject:subject}" -o table
```

Wait roughly 30 seconds for propagation and rerun `02 Azure landing zone Continuous Delivery`. The plan identity fixes the current `terraform init`; the apply identity prevents the next stage from failing after approval. The CLI commands and exact-match requirement are documented under [Azure federated identity credentials](https://learn.microsoft.com/en-us/cli/azure/identity/federated-credential?view=azure-cli-latest).

## Longer-term choices

- Upgrade when Microsoft releases an ALZ bootstrap version supporting immutable GitHub subjects. Then let that version manage the credentials and remove the temporary `*-immutable` credentials after validation.
- Fork/patch the bootstrap module so [subject generation](C:/Users/gregt/LocalCode/Lab/ALZ/output/bootstrap/v7.2.1/modules/github/locals.tf:28) incorporates the owner and repository IDs. Be aware that editing generated output may be overwritten by a future `Deploy-Accelerator`.
- As a compatibility workaround, opt the `alz-mgmt` repository out of immutable subjects using GitHub’s OIDC REST API while retaining the existing `repository`, `environment`, and `job_workflow_ref` customization. That should make the existing name-only Azure credentials work, but it gives up GitHub’s immutable-subject security improvement. [GitHub OIDC REST API](https://docs.github.com/en/rest/actions/oidc).

Do not try to solve this by adding Azure role assignments, opening the storage account firewall, or introducing a client secret; none addresses the failed OIDC token exchange.
